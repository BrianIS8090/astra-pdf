# Участие в разработке

Спасибо за интерес к Astra PDF. Для ошибки создайте issue с шагами воспроизведения, ожидаемым и фактическим результатом, версией приложения, сборкой Windows и масштабом экрана. Прикладывайте только документы, которые разрешено публиковать. Для ошибки печати укажите принтер, драйвер, диапазон и параметры печати.

Перед большой доработкой откройте предложение, чтобы согласовать её объём. Исправления присылайте отдельными pull request с описанием поведения и результатов проверки.

## Среда и проверки

Нужна Windows x64. Из корня проекта в PowerShell:

```powershell
.\scripts\setup.ps1
.\scripts\build.ps1 -Test -Release
```

Скрипт устанавливает инструменты в локальную папку `tools`; системный PATH не меняется. Используйте закреплённую версию Rust и Cargo.lock. Отступ — два пробела, комментарии в коде — на русском. Форматирование — `cargo fmt`, статическая проверка — `cargo clippy --locked --all-targets -- -D warnings`, с окружением из `scripts/build.ps1`.

GitHub Actions выполняет сборку, тесты Rust, форматирование и статическую проверку на Windows Server. Он не заменяет проверку интерфейса и принтеров в Windows 11.

Для полной проверки в интерактивной сессии Windows 11 с Microsoft Print to PDF:

```powershell
python -m pip install -r .\scripts\test-requirements.txt
.\scripts\verify.ps1 -Python python
```

Результаты сохраняются в новом каталоге `test-output`. Не добавляйте в Git документы пользователей, инструменты, зависимости, сборки, ключи и локальные журналы. При изменении поведения добавляйте проверку, которая подтверждает результат для пользователя.

## Выпуски

Критерии стабильного выпуска перечислены в [RELEASE_PLAN.md](RELEASE_PLAN.md). Публикация предварительного выпуска не закрывает незавершённую приёмку системной печати. Перед упаковкой исходники и EXE сверяются с полным прогоном; после упаковки проверяются контрольные суммы и запуск извлечённого приложения.
