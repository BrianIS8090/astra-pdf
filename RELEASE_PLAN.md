# Готовность к выпуску Astra PDF

Цель пользователя: приложение готово к проду. Исходный объём: быстрый и лёгкий PDF-просмотрщик на Rust, нативная Windows 11, страницы, слои и печать.

Готовность пока не подтверждена. Кандидат 1.0.0-rc.3 прошёл 27 тестов кода, 24 сценария окна и 10 проверок детального режима, проверки устойчивости движка и виртуальной печати. Добавлены запрошенные миниатюры, непрерывная прокрутка, масштаб без пустого экрана, иконка и центрирование номера. Незавершённая приёмка системного сохранения печати описана ниже и в отчёте проверки.

## Критерии выпуска

1. Документы открываются из системного диалога, аргумента и перетаскивания; Unicode-пути работают. Ошибки чтения и повреждённые файлы не завершают окно. Повторное открытие после ошибки работает.
2. Движок документа работает отдельно от интерфейса. Сбой, зависание или превышение памяти завершают конкретный запрос и позволяют открыть следующий документ. Обмен данными и очередь запросов ограничены. Это изоляция сбоев, а не обещание полноценной песочницы безопасности.
3. Страницы, переход по номеру, масштаб, прокрутка, поворот, клавиатура и изменение размера окна подтверждены поведением интерфейса. Положение страницы и состояние управления согласованы с изображением.
4. Реальные PDF-слои переключаются независимо; исходная видимость, блокировки и взаимоисключающие группы соблюдаются. Состояние после переключения, сброса и печати проверено по изображению. Исходный файл остаётся неизменным.
5. Системная печать поддерживает весь документ, диапазон, копии и параметры принтера; сохраняет выбранные слои, поворот и пропорции. Отмена, ошибка подготовки/отрисовки/драйвера и закрытие окна во время задания имеют проверенный исход. Успех означает принятие задания системой печати, а не физический выход бумаги.
6. Отзывчивость и память проверены на корпусе документов: текст, растровые сканы, чертежи, несколько размеров страниц, сотни страниц, многослойные файлы и повреждённые входные данные. Измеряются полный пользовательский путь и рабочий набор памяти, а не только экспорт первой страницы.
7. На Windows 11 проверены нативные диалоги, масштаб интерфейса, клавиатура и читаемость элементов. Пакет запускается из чистой распакованной папки без Rust и окружения разработки.
8. Выпуск имеет фиксированные зависимости, проверку известных уязвимостей, актуальные лицензии, согласованные версии, руководство, контрольные суммы и архив исходников. Проверки запускаются одной командой, проверяют свежие результаты и завершаются ошибкой при неполноте.
9. Миниатюры отражают страницы и выбранные слои, загружаются по мере просмотра и открывают страницу нажатием. Непрерывный режим показывает соседние страницы и согласует номер с прокруткой; доступен режим одной страницы. Масштабирование сохраняет изображение во время перерисовки. Номер выровнен по центру, собственная иконка встроена, интерфейс проверен визуально и интерактивно.

## Свидетельства

Для каждого критерия нужны актуальные результаты исполнения, файлы проверки или воспроизводимый сценарий. Старый отчёт 0.1.0 хранится как исходная точка, но не заменяет проверку нового выпуска. Итоговый отчёт должен явно отличать подтверждённое поведение от ограничений и непроверенной аппаратной совместимости.

## Текущая работа

- Критерии 1–4 и 6 подтверждены свежей автоматической проверкой от 2 октября 2026.
- По критерию 5 подтверждены GDI-печать всего документа и диапазона с нужными слоями, отмена, восстановление и закрытие во время задания. В разблокированной сессии системный диалог принял диапазон 2–3 и открыл сохранение PDF. Инструмент Computer Use не смог адресовать поле вложенного диалога сохранения, поэтому файл из этого сценария пока не получен. Приёмка остаётся pending до независимой проверки сохранённых страниц.
- По критерию 7 проверены окна, диалоги открытия/отмены печати и масштаб 200%, размеры окна 1120×1040 и 1800×1200; физический переход между мониторами не проверен.
- По критерию 8 проверены зависимости по RustSec без предупреждений, все лицензии, согласование версии EXE и свежая переносимая сборка. Упаковка проверяет контрольные суммы исходников/EXE, целостность ZIP и запуск после извлечения; итог хранится в RELEASE.json.

- Критерий 9 подтверждён новыми автоматическими сценариями, снимками и интерактивной проверкой. Подсветка миниатюры проверяется по пикселям после перехода по номеру.

Полный подтверждённый прогон: `test-output\verify-20261002-073922-8ede93ac`.

## Продолжение системной проверки

Для отдельной проверки системного сохранения выполнить из доступной сессии Windows:

```powershell
python .\scripts\verify_native_print.py 'test-output\verify-20261002-073922-8ede93ac'
```

Сценарий проверяет контрольную сумму исполняемого файла, вводит диапазон 2–3 с проверкой фокуса и допускает только Microsoft Print to PDF. После сохранения он сравнивает число, порядок и пиксели страниц с контрольной печатью. Только успешное сравнение создаёт свидетельство приёмки и меняет её статус. Проверка остановки при LockApp выполнена: просмотрщик не запущен, статус остался pending. Проверяющий код прошёл четыре сценария: правильные страницы, неверное число, неверные страницы и обратный порядок.

Этот сценарий входит в исходники rc.3. Для стабильного выпуска после успешной приёмки нужны новая полная проверка согласованной версии, повтор системной печати на её исполняемом файле и новая упаковка. Результат старого EXE не переносится на другой EXE автоматически.

Предварительные выпуски публикуются в GitHub Releases. Подписание сертификатом пока не настроено. Новые функции вне исходного объёма не заменяют закрытие дефектов основных сценариев.
